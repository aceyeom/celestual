# 제약 조건 & 아키텍처 결정 (2단계 진입 전)

## 발견된 하드 제약: 클라우드 환경은 네이버 접속 불가

이 클라우드 세션의 네트워크 정책이 외부 호스트 아웃바운드를 전면 차단한다.
실제 테스트 결과:

| 호스트 | 결과 |
|---|---|
| `search.naver.com` | 403 CONNECT tunnel failed |
| `openapi.naver.com` (네이버 공식 검색 API) | 403 |
| `m.search.naver.com` | 403 |
| `example.com` / `google.com` (대조군) | 403 |
| WebFetch → search.naver.com | "unable to fetch" |
| WebSearch | US 전용 — 네이버 블로그 결과 미반환 |

즉 **이 세션 안에서 네이버 상위글 자동 수집·자동 포스팅의 "실행"은 불가능**하다.
(환경 설정에서 Network access를 넓혀 도메인을 추가하면 접속 자체는 열 수 있으나,
아래 이유로 실행은 여전히 사용자 PC를 권장한다.)

## 아키텍처 결정: "코드는 여기, 실행은 사용자 PC"

네이버의 블로그 차단(저품질·어뷰징 판정)은 주로 다음에서 발생한다:

1. **데이터센터 IP** (클라우드 컨테이너 IP)
2. **헤드리스 브라우저 지문** (자동화 탐지)
3. **기계적 속도** (사람보다 빠른 타이핑·클릭·연속 포스팅)
4. **신규·무로그인 세션**

클라우드에서 수집·포스팅하면 위 4가지에 **모두** 걸린다. 따라서 "차단되지 않는
방법"이라는 목표와 클라우드 실행은 근본적으로 모순이다.

**결론:**
- 수집·분석·생성·포스팅 **코드/도구는 이 저장소(`food_portal/`)에서 만들어
  커밋**한다.
- **실행은 사용자 PC**에서 — 실제 브라우저 프로필, 로그인된 네이버 세션,
  정상(가정용) IP, 사람다운 속도로.
- 가능하면 네이버 **공식 API**(검색/블로그)를 수집에 활용해 차단 위험을 낮춘다.
  (단 클라이언트 ID/Secret 필요 — 사용자 발급.)

## 2단계 진행 방식 — 결정 대기

네이버 상위글 역설계(목차·글자수·어투·형태 분석)를 어떻게 할지:

- **(A) 로컬 실행 도구 제작 (권장)** — Playwright 기반 수집·분석 스크립트를
  만들어 커밋하고, 사용자가 PC에서 실행해 결과를 뽑는다. 차단회피 목표와 일치.
- **(B) 상위글 URL 직접 제공** — 각 주제 키워드의 네이버 1~3위 블로그 URL/본문을
  사용자가 알려주면, 그 구조를 정밀 분석. 가장 빠르고 정확.
- **(C) 지식 기반 분석으로 진행** — 네이버 식품블로그 상위노출 패턴(C-rank/DIA,
  목차·글자수·이미지·어투)을 정리해 바로 3단계(본문 생성)로.

> 사용자 메모: 이전 질문은 보류(dismiss)되었고, "지금까지 작업을 food_portal로
> 이동"하라는 지시가 내려와 이 문서들을 생성함. 2단계 방식은 다음 지시 대기.
