# 2단계 — 네이버 1위 글 역설계 방법론

목표: 각 주제 키워드로 검색했을 때 **식품업종 상위(1위)** 에 노출되는 블로그
글의 **목차·내용·형태·어투**를 정량 분석해, 우리 글이 그 구조를 넘어서도록
역설계한다.

## 네이버 블로그 상위노출의 두 축

네이버 통합검색 블로그 순위는 크게 두 알고리즘의 곱이다.

### ① C-Rank — "이 블로그를 믿을 수 있나" (출처 신뢰도)
- **맥락(Context)**: 블로그 주제의 일관성. 식품/수입/유통 한 우물일수록↑
- **내용(Content)**: 글의 품질·독창성·정보량 누적
- **연결(Chain)**: 체류시간, 스크랩, 댓글, 공감, 재방문(= 사람들이 반응하는가)
- → **단기 조작 불가.** 한 분야로 꾸준히 쌓아야 한다. (우리의 "3축 전략"이
  식품 한 주제에 집중하는 이유)

### ② D.I.A. / D.I.A.+ — "이 문서가 좋은가" (문서 품질)
- 문서 자체의 **경험·정보성·구체성**을 봄. 실제 데이터·수치·직접 촬영 이미지가
  강력한 신호.
- → **TAAMs 실데이터(통관 수치·단가·지도)가 여기서 결정적 경쟁력.** 경쟁 블로그가
  못 가진 1차 데이터를 우리는 가진다.

## 역설계로 추출할 정량 지표

각 키워드의 상위 N개 글에서 아래를 측정 → 중앙값/분포로 "이기는 공식" 산출.

| 지표 | 의미 | 추출 방법 |
|---|---|---|
| **글자수** | 본문 총 글자수(공백 제외) | 본문 컨테이너 텍스트 길이 |
| **이미지 수** | 사진/표/GIF 개수 | 이미지 모듈 카운트 |
| **소제목(목차) 수·구조** | H2급 소제목 개수와 흐름 | 큰 폰트/볼드 텍스트 모듈 |
| **문단 수·평균 문단 길이** | 가독성 | 줄바꿈 기준 분할 |
| **어투** | 정중체(~습니다) vs 친근체(~요/~네요) 비율 | 문장 종결어미 정규식 |
| **키워드 밀도** | 타깃 키워드 반복 횟수·위치(제목/첫문단/소제목) | 문자열 카운트 |
| **태그** | 사용 해시태그 | 태그 영역 |
| **동영상 유무** | 영상 삽입 여부 | 비디오 모듈 |
| **외부링크/표** | 표·링크 사용 | 테이블/링크 카운트 |

## "이기는 공식" 산출 규칙

- **글자수**: 상위글 중앙값의 **1.1~1.3배** (단, 2,500자 미만이면 최소 2,500자).
  억지로 길게 X — 정보 밀도 우선.
- **이미지**: 상위글 중앙값 이상 + **직접 촬영/제작 이미지 1장 이상** (DIA 신호).
  → 우리는 TAAMs 조회 결과를 **차트·지도 이미지**로 생성해 삽입(독창성↑).
- **소제목**: 상위글 평균 구조를 따르되, 각 소제목에 **TAAMs 수치 1개씩** 배치.
- **어투**: 상위글 다수 어투에 맞춤(식품 정보성 글은 보통 **정중체+친근체 혼합**).
- **첫 문단**: 타깃 키워드 + 핵심 결론(수치) 선제시 (이탈률↓, 체류↑).
- **독창성 레버**: 경쟁글에 없는 **TAAMs 1차 데이터**(통관 건수·단가·수출사·지도)를
  반드시 1개 이상 — 이게 D.I.A.를 통과시키는 핵심.

## 수집 실행 — 왜 사용자 PC인가 (재확인)

- 클라우드(이 세션)는 네이버 차단 + 데이터센터 IP → 수집 자체가 막히고, 설령
  뚫어도 포스팅 단계에서 계정이 위험.
- 그래서 **수집·분석 도구를 `food_portal/src/tools/`에 만들어 커밋**하고, **사용자
  PC에서 실행**한다. 상세 사용법은 `src/tools/README.md`.

## 수집 소스 (도구가 지원)

> ❗ 네이버 공식 "검색 API"는 **신규 애플리케이션 등록에서 제공되지 않는다**
> (개발자센터 "사용 API" 목록에 검색 없음, 2026-10 확인). 따라서 공식 API
> 방식은 폐기하고 아래 두 가지로 상위글 URL을 확보한다.

1. **[기본] 통합검색 결과 스크래핑** — Playwright(헤드풀)로 네이버 블로그탭
   검색결과 페이지를 직접 열어, 노출 순서대로 상위 글 URL을 수집. **실제
   통합검색 순위를 그대로 반영**하므로 가장 정확하다.
2. **[대체/보강] 실제 순위 URL 직접 입력** — 통합검색에서 눈으로 본 1~3위
   URL을 `urls.json`에 넣으면 그 글들을 우선 분석.

두 경우 모두, 확보한 글 URL의 **본문 구조 분석은 Playwright(헤드풀, 사람 속도)** 로
수행한다. 반드시 사용자 PC에서 실행한다(클라우드 차단·데이터센터 IP 문제).
